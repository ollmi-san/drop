# DROP WIKI

Dieses Dokument erklärt wichtige Begriffe, die wir während 
der Entwicklung von DROP benutzen.

------------------------------------------------------------

API
(Aussprache: Äi-Pi-Ei)

API = Application Programming Interface

Eine API ist eine Schnittstelle zwischen zwei Programmen.

Einfach erklärt:
Stell dir vor, DROP möchte das Wetter wissen.
DROP fragt die Wetter-API: "Wie wird das Wetter heute in 
Berlin?"
Die Wetter-API antwortet: "22 Grad, sonnig."
DROP muss das Wetter also nicht selbst berechnen.

------------------------------------------------------------

JSON

JSON = JavaScript Object Notation

Ein Datenformat.
Man kann sich JSON wie einen digitalen Steckbrief vorstellen.

Beispiel:
Name = Schwarzer Hoodie
Farbe = Schwarz
Größe = L
Material = Baumwolle

Fast alle modernen Apps tauschen Daten im JSON-Format aus.

------------------------------------------------------------

JSONB

Das B steht für "Binary".
JSONB ist eine besonders schnelle Version von JSON in 
PostgreSQL.

Vorteil: Wir können jederzeit neue Informationen hinzufügen, 
ohne die Datenbank komplett umzubauen. Für DROP perfekt 
geeignet.

------------------------------------------------------------

Backend
(Aussprache: Bäck-End)

Das Backend ist der Teil der App, den der Nutzer niemals sieht.

Hier passieren:
- Daten speichern
- Login
- KI
- Server
- Datenbank

------------------------------------------------------------

Frontend
(Aussprache: Front-End)

Alles, was der Nutzer sieht.

Zum Beispiel:
- Buttons
- Avatar
- Wardrobe
- Stage
- Menüs

------------------------------------------------------------

Supabase
(Aussprache: Suh-puh-base)

Supabase ist unser Backend.

Es übernimmt:
- Login
- Datenbank
- Bilder
- Cloud
- Benutzer

------------------------------------------------------------

PostgreSQL
(Aussprache: Post-gres-Q-L)

Die Datenbank hinter Supabase.
Hier werden alle Daten gespeichert.

------------------------------------------------------------

Datenbank

Eine riesige digitale Tabelle.

Hier werden gespeichert:
- Kleidung
- Nutzer
- Outfits
- Styles
- Bilder

------------------------------------------------------------

Garment
(Aussprache: Gar-ment)

Englisch für: Kleidungsstück.

------------------------------------------------------------

Garment DNA

Der digitale Steckbrief eines Kleidungsstücks.

Zum Beispiel:
- Farbe
- Material
- Länge
- Passform
- Stil
- Layer

Alles wird einmal erkannt und gespeichert.

------------------------------------------------------------

User Style DNA

Der digitale Steckbrief des persönlichen Kleidungsstils.

Beispiele:
- Lieblingsfarben
- Lieblingsmarken
- Streetwear Score
- Minimal Score
- Lieblingskombinationen

Dieser Steckbrief entwickelt sich mit der Zeit.

------------------------------------------------------------

Template

Eine Vorlage.

Zum Beispiel gibt es eine Vorlage für:
- Hoodie
- Mantel
- Blazer
- Jeans

Die KI muss nicht jedes Kleidungsstück komplett neu erfinden.

------------------------------------------------------------

Layer

Die Reihenfolge der Kleidung.

Zum Beispiel:
T-Shirt → Hoodie → Jacke → Mantel

------------------------------------------------------------

Rendering
(Aussprache: Ren-der-ing)

Rendering bedeutet: Der Computer berechnet ein Bild.
Bei DROP: Der Avatar wird dargestellt.

------------------------------------------------------------

Three.js
(Aussprache: Three Jay Ess)

Eine JavaScript-Bibliothek.
Mit ihr bauen wir unsere 3D-Welt.

------------------------------------------------------------

Scope

Der Umfang eines Projektes.

------------------------------------------------------------

Scope Creep
(Aussprache: Skoup Kriep)

Scope = Umfang
Creep = schleicht sich langsam ein

Bedeutung: Immer neue Ideen kommen dazu. Das Projekt wird 
größer. Dadurch wird nichts fertig.

Deshalb sammeln wir neue Ideen zuerst im Ideenparkplatz.

------------------------------------------------------------

MVP

Minimum Viable Product.
Die erste funktionierende Version. Nicht perfekt. Aber 
benutzbar.

------------------------------------------------------------

Roadmap

Der Entwicklungsplan.

Welche Funktionen bauen wir:
Phase 1 → Phase 2 → Phase 3

------------------------------------------------------------

Architektur

Der Bauplan der gesamten Software.
Wie alle Teile zusammenarbeiten.

------------------------------------------------------------

Modul

Ein eigenständiger Baustein.

Zum Beispiel:
- Avatar
- Wardrobe
- Fashion Guide
- Garment DNA

------------------------------------------------------------

Embedding
(Aussprache: Em-bed-ding)

Eine mathematische Beschreibung.
Dadurch kann KI erkennen, welche Dinge ähnlich sind.

------------------------------------------------------------

Confidence Score

Wie sicher sich die KI bei einer Erkennung ist.

Beispiel:
0,99 = sehr sicher
0,52 = eher unsicher

------------------------------------------------------------

Vision AI

Eine KI, die Bilder versteht.

Sie erkennt zum Beispiel:
- Kleidung
- Farben
- Materialien
- Formen

------------------------------------------------------------

AI Agent

Eine KI, die Aufgaben selbstständig erledigt.

Zum Beispiel:
"Analysiere meinen Kleiderschrank."
oder
"Erstelle automatisch drei Outfits."

------------------------------------------------------------

Repository (Repo)

Der Speicherort des gesamten Projekts.
Meist GitHub.

------------------------------------------------------------

Git

Ein Versionsverwaltungssystem.
Man kann jederzeit ältere Versionen des Projekts 
wiederherstellen.

------------------------------------------------------------

Commit

Ein gespeicherter Entwicklungsstand.
Wie ein Speicherpunkt in einem Videospiel.

------------------------------------------------------------

Branch

Ein Entwicklungszweig.
Ideal zum Testen neuer Funktionen, ohne die Hauptversion 
kaputt zu machen.

------------------------------------------------------------

Tech Debt

Technische Schulden.
Eine schnelle Lösung heute, die später noch einmal sauber 
gemacht werden muss.

------------------------------------------------------------

Refactoring

Code aufräumen und verbessern, ohne neue Funktionen 
hinzuzufügen.

------------------------------------------------------------
